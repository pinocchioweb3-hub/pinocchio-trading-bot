# 真錢路徑：本地部位帳「讀失敗 ≠ 確認空帳」（v163・監督員 r54）

日期：2026-07-31　狀態：已落地（模板＋真錢副本），⛔ 尚未在線上觸發過
前一輪：r53／v162（孤兒擋單閘的「未知」分支）——本輪是 r53 next_step 候選④「同族型別稽核」的執行結果。

## 一、稽核範圍與方法

r53 修完孤兒閘後留下一條待辦：**同一族的「未知 vs 確認」型別問題，再掃一遍真錢路徑其他回傳值**，
確認沒有第二處把「查詢／讀取失敗」壓成空值。方法＝逐一檢視 `consume_intents.py` 內所有
`except → return 空值` 的出口，並追到呼叫端問一句：**這個空值在下游會被當成「確認沒有」嗎？**

結果：找到一處，而且比 r53 修的那處更致命——`_load_positions()`。

## 二、破口（舊碼）

```python
def _load_positions() -> dict:
    try:
        return json.loads(POS_STATE.read_text(encoding="utf-8"))
    except Exception:
        return {"open": {}, "day_pnl": {}}     # ← 讀失敗＝「沒有倉、今天沒虧損」
```

同一個空值在同一輪同時餵三個地方（全部無聲）：

| # | 呼叫端 | 讀到空值的後果 |
|---|--------|----------------|
| ① | `breaker_tripped(day_pnl)` | 日 60U／週 150U 熔斷**整個消失**——該停手的日子照接新單 |
| ② | `dup_open_same_side(open)` | 同幣同向擋單閘瞎掉——OKX hedge 併倉、曝險無聲翻倍、已實現損益無法歸屬（v130 已在模擬盤實證會虛增 R） |
| ③ | 下單成功後的寫回 | 拿這本空帳 `_save_positions()` 蓋掉真檔 ⇒ **既有倉與近 14 天熔斷損益被永久抹掉**，那些倉就此脫帳成孤兒 |

③ 是三者中唯一**不可逆**的：不是「這輪判斷錯」，是「歷史被刪掉」。

## 三、觸發條件不需要網路故障

舊 `_save_positions()` 用 `Path.write_text()`＝**先截斷再寫**的非原子寫。行程在中途被殺
（排程逾時／休眠／當機／磁碟滿）就留下半截 JSON，之後**每一輪**都讀壞。
本機已有同類前例（`atk_live.utf16-corrupt.log.bak`），不是理論風險。
換言之：舊碼會自己製造那個壞檔，再自己把壞檔誤讀成空帳。

## 四、v163 修法

1. `_load_positions() -> dict | None`：三態。
   - 檔案不存在＝首跑，回合法空帳；
   - JSON 壞／IO 錯／結構不對＝回 `None`（未知）並記 `pos_state_unreadable`。
2. `_save_positions() -> bool`：改「暫存檔 ＋ `os.replace()`」原子寫（不再自己製造壞檔）；
   失敗回 `False` 並記 `pos_state_write_fail`（不再無聲吞掉）。
3. 呼叫端全部改成「未知就不動」：
   - `manage_positions()`：帳本未知 ⇒ 不對帳、不平倉、回 `None`（走 r53 既有的「未知不接新單」分支）；
   - 主迴圈：輪首讀不到 ⇒ 本輪不接新單、不記 done；逐單再讀一次（同輪中途才壞掉也要擋）；
   - 寫回路徑：⛔ 絕不用空帳覆蓋；讀不到或寫不成 ⇒ 印 🚨 並記帳（那筆倉下輪由孤兒閘接手，
     它的止損仍掛在交易所）。
4. `pos_state_*` 兩個新故障類別排在傳輸類之前：本地帳壞掉不是「這輪送不出去」，
   而是「風險上限暫時不存在」，且與網路無關、修法完全不同（要人去看那個檔案）。

⛔ 告警文案明寫「不要直接刪掉那個檔案」——刪掉等於把在場倉與近 14 天熔斷損益一起清零。
