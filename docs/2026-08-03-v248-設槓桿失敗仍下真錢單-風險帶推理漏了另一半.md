## 二、根因：v155 的「風險帶」只想過偏離的一半

`place()` 進場前呼叫 `ensure_leverage()`。v155（監督員 r45）當時的決定是：
**設槓桿失敗只在「風險帶」擋單，風險帶＝算出的 lev < 上限**。理由寫在碼裡：

> lev == LEVERAGE 時舊值不可能更高（本執行器只設 ≤ 上限）⇒ 擋單純屬白擋，維持照下。

這個推理只涵蓋一種偏離：**交易所側卡在比意圖更高的舊值**（保證金被壓小、清算可能
縮進止損內＝破 v84 不變式）。它從來沒想過對稱的另一半：**交易所側比意圖更低**。

而 SOXL 就是另一半：`59102 Leverage exceeds the maximum limit` ＝**該合約的槓桿上限
低於本執行器的上限**。模板第 45 行那句註解「美股代幣永續上限 25x」對 SOXL 不成立。
於是：設槓桿失敗 → `ensure_leverage` 回 False → 但 `lev == 上限`、不在風險帶 →
**三腿照送**，倉落在交易所預設的 3x。

事後那道讀回閘（v171）按設計就是「只記錄與告警：不自動調槓桿、不自動平倉、不擋新單」
——它只能在錢已經下去之後喊 mismatch。**那一刻沒有任何東西攔得住。**

同物種第 69 次的變體：前 68 次是「量不到被折成沒有」；這次是**「已知失敗被判定為
不必處理」**——資訊沒被弄丟，是被主動放棄了。

## 三、實際後果（分開講，不誇大）

1. **SOXL 這一倉是規格外的。** 3x 而非 20x ⇒ 逐倉保證金約為原計畫的 20/3 ≈ **6.7 倍**。
   ⚠️ 誠實補一句方向：對**空單**而言，槓桿更低代表清算價離進場更**遠**，所以系統
   那句「清算距離可能已縮到止損之內」是通用措辭，在這個方向上不是本次的實際危害。
   本次的實際危害是**佔用保證金遠超計畫**與**部位不符合下單當時的風險模型**。
2. **止損仍在交易所側。** 三腿都帶 `--slTriggerPx`（v157/v158），這倉不是裸的。
3. **管線沒有停擺**——這點要對帳本的措辭做校正。`oversight_ledger` 寫「管線實質停擺」，
   但讀回閘按設計不擋新單，真錢執行器每輪照跑、既有倉照管。停的不是管線。
4. **停的是監測訊號。** 只要這倉活著，每輪都記一筆 `lev_mismatch` ⇒
   `consecutive_fail_rounds` 永不歸零、`last_ok_ts` 凍住 ⇒ 任何**其他**故障類別都會被
   這個長期噪音蓋掉。這正是 WLFI 孤兒倉那 58 小時／2998 輪的形狀，這次又來一次。

## 四、已修（v248）

`place()` 改為：**只要 `ensure_leverage` 回 False，整筆不下**，與算出的 lev 落在哪一段無關。

- 這是**只會讓單變少、永遠不會變多**的方向，是對真錢路徑最安全的一類改動。
- 網路類暫時失敗 ⇒ 延後一輪重試（每分鐘一輪）。
- 59102 這種結構性擋不住的 ⇒ 該一直擋。⛔ 開一個「槓桿設不成功」的真錢倉，
  本來就沒有正確版本。
- ⚠️ **副作用講明**：上限高於該合約上限的標的，從此**永遠下不了單**，而不是自動降級
  成該合約的上限。這類標的每輪會留下一筆 `leverage_fail`＝擋在哪裡看得見，不是靜音。
