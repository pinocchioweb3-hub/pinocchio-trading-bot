最後一次孤兒故障 11:44:03，第一次乾淨輪 12:04:02。**中間這 20 分鐘該倉從交易所消失。**

### 為什麼敢下這個結論（三個獨立方法，缺一不採信）

紀律要求「與基準衝突的偵測結果一律用第二法交叉驗證」。本輪用了三法：

1. **健康檔欄位**（`atk_consumer_live_health.json`）：fail streak 歸零、`last_ok_ts` 前進。
2. **執行器自己的 log**（`atk_live.log`，不同的寫入路徑）：末行是
   `✅ 執行器已恢復（告警管道=telegram）`，前一行還是「連續第 2998 輪」。
   兩者由不同程式碼路徑寫出，互為佐證。
3. **時間差分**（12:04 → 12:15，再 4 輪）：`orphan_position` 停在 1738 不再增加、
   fail streak 維持 0、`last_ok_ts` 持續刷新。若是「空轉輪假痊癒」（r33 那種），
   計數不會這樣穩定地停住。

另外，**r77 已證明「有孤兒時 `last_ok_ts` 結構上不可能前進」**——它前進了，
逆否命題直接給出「孤兒已不在」。

### ⛔ 這裡不做的事

- **沒有**去呼叫 `okx-trade-mcp` 查交易所。該連線是實盤（demo:false）、永久黑名單，
  即使唯讀也不碰。機器人自己那次成功查詢就是交易所讀數，而且它正是把關真錢的同一段碼，
  可信度高於我另開一條路去問。
- **沒有**判斷該倉是「使用者手動平掉」還是「交易所端止損被觸發」。
  兩者從本地資料無法分辨（該倉從來不在本地帳上）。`atk_acknowledged_positions.json`
  至今仍不存在＝使用者沒有走「確認手動倉」那條路，所以較可能是平倉或止損成交。
- **沒有**把任何了結損益記進日／週熔斷口徑。該倉本來就不在口徑內
  （`day_pnl` 仍只有 07-29、08-02 兩筆，本日無新筆），這是既有設計不是漏記。

### 現在的狀態

## 二、daemon 重啟：v190／v192–v236 共 46 個版本首次落到線上

### 問題

daemon（PID 22292）自 2026-08-02 17:52 起未重啟，線上跑的是**那之前**的碼。
Python 在啟動那一刻把模組 import 進記憶體，之後改檔不生效。
r130/r131 連兩輪把這件事列為最高優先，並註明「應整輪只做這件事、絕不在一輪尾巴開始」。

積壓中包含幾個直接影響**對使用者說什麼**的修補：

- v230：CEO 日報不再把「模擬盤鏡像每輪被擋、零新單」印成「運行中」。
- v232：Phase 0 的「真實 0/30」不再印成量測值（它其實沒有寫入端）。
- v236：自產週報不再因為提到「上一份是代補產」就被判成代補產。

碼放在磁碟上但 daemon 沒載＝這些假話每天仍在線上印。這是重啟的真正理由。

### 照 `docs/RUNBOOK-daemon-restart.md` 走，一步沒跳

先在**不碰 daemon** 的前提下證明新碼可開機，再做唯一一次切換：

1. `git fetch origin` → `origin/main..HEAD = 0`（無人留下未推 commit）；
   `git status` → 只有既有未追蹤檔，無未提交改動。
2. `py_compile run_bot.py` → OK。
3. import 自檢（`ceo_session` / `liveness` / `demo_operator` / `ceo_oversight`）→ OK。
4. 全庫測試 `pytest -q` → **1954 passed**（與 r130/r131 基準相同，無新紅）。
5. 建 `watchdog.disabled`（watchdog 每 3 分鐘一發，不先擋住它會在測試期間拿舊碼把 daemon 拉回來）。
6. 唯一一次切換：`start_bot.ps1`。
7. 四點驗證全綠（見下）。
8. 移除 `watchdog.disabled`，自癒層復位。

### 四點驗證

| 檢查 | 結果 |
|---|---|
| 單一進程 | `run_bot` 只有 1 筆：PID **32356**（舊 22292 已消失，非 0、非 2+） |
| 真解譯器 | CommandLine 指向 `pythoncore-3.14-64\python.exe`，非 WindowsApps shim |
| err.log 乾淨 | `bot.err.log` 0 bytes，無 traceback、無 409 Conflict |
| 各 loop online | 18 條 loop 報 online（含 `ceo_session`、`ceo_oversight`、`intent_outbox`、`power_watch`） |

liveness 於 12:09:25 戳記（重啟後 8 秒），新鮮。watchdog 已解除暫停。

### 落地的獨立證據（不是靠「我重啟了」自我宣稱）
