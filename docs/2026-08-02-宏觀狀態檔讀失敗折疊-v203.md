# v203：宏觀狀態檔「讀不出來」不再折成「本來就沒有」（同物種第 23 次）

日期：2026-08-02（監督員 r98）
檔案：`l3_dispatcher/macro.py`、`l3_dispatcher/synthesizer.py`

## 折疊點與各自的下場

同一個壞習慣（`try: ... except: pass` 把「檔在但讀不出來」與「本來就沒有」折成同一條路），
這一次落在兩個狀態檔上，而兩者的正確處置**方向相反**。

### Site B — `daily_macro_state.json`（重啟去重戳記）

舊碼：

```python
try:
    if dm_state.exists():
        st = _json.loads(dm_state.read_text(encoding="utf-8"))
        age_h = (... - st.get("last_sent_ts", 0)) / 3600
        if age_h < 6:
            run_on_startup = False
except Exception:
    pass
```

讀失敗 → `run_on_startup` 維持 True → **照發一份完整 Daily Macro**。
watchdog 三層自癒本來就會重啟，於是壞檔期間**每一次重啟都再發一份、且無上限**——
正好是 v23-2 這段去重邏輯當初存在的理由。

`st.get("last_sent_ts", 0)` 的預設值 `0` 讓「合法 JSON 但缺鍵」也折成
age_h≈488000 小時＝「從來沒發過」。`[]` 這種合法 JSON 非 dict 則讓 `.get` 直接
AttributeError，被同一個 `except` 吞掉，結果完全同形。

### Site A — `pulse_state.json`（每小時 pulse 的差分基準）

讀失敗 → `last_text=None` → 下游 `synthesize_hourly_pulse` 只看這個值是否為空，
於是對 LLM 送出一句**假的事實陳述**：

> \#\# 上一次報告：無（今日第一則，輸出基準描述）

下場：壞檔期間每小時都送一份全量基準描述，並對使用者宣稱那是今日第一則，
差分規則「已講過且沒變的禁止再講」整個失效。這是紅線③的形狀。

## 行為探針（跑改動前的碼，非只讀碼推論）

| 情境 | 啟動段是否重發 |
|---|---|
| 對照組·健康檔（10 分鐘前發過） | 否 ✅ |
| 半截 JSON（斷電殘檔） | **是 ❌** |
| 合法 JSON 但非 dict（`[]`） | **是 ❌** |
| dict 但缺 `last_sent_ts` | **是 ❌** |
| 對照組·檔真的不存在 | 是 ✅（真·第一次，本來就該發） |

## 修法

新增三態讀取（沿用 v200 `auto_tuner.py` 既有慣例，非另立第三套）：
`STATE_OK` / `STATE_MISSING` / `STATE_UNREADABLE`，配 `_atomic_write_state`
（temp + flush + fsync + os.replace）與 `_preserve_bad_state`（壞檔留 `.bad` 鑑識副本並出聲）。

- `_daily_macro_startup_skip()`：`missing` → 照發（真·第一次）；`unreadable`／缺鍵／型別不對
  → **保守跳過並出聲**。理由是兩個方向的代價不對稱：少發最多延後到主迴圈 00:00 UTC
  那班（不會永久遺失），重發卻是每次重啟都來一份、無上限。
- `_mark_daily_macro_sent()`：改原子寫、**回傳 bool**、寫失敗出聲。舊版 `except: pass`
  讓「戳記沒寫進去」與「有寫進去」對外完全同形，下次重啟就再發一次而無人知道為什麼。
- `_load_pulse_baseline()` + `synthesize_hourly_pulse(baseline_status=...)`：
  讀不出來時提示詞改講「**讀取失敗，基準未知**——這不等於沒有上一則，禁止宣稱這是今日第一則」，
  並要求開頭標明「差分基準暫時遺失，本則為全量描述」。記憶體裡已有基準時一律走差分（狀態旗標不得蓋掉真的有的基準）。
