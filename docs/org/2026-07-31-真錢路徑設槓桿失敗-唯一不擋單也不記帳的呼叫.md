# 真錢路徑上唯一「失敗了既不擋單、也不進健康帳」的呼叫：設槓桿

日期：2026-07-31（監督員 Layer 2，r41）
檔案：`tools/atk_consumer/consume_intents.py`（模板）→ `consume_intents_live.py`（由 `make_live_copy.ps1` 產生）
行號：`ensure_leverage()` 415–429、呼叫點 `place()` :612、對照組 `query_fail` :633–636
嚴重度：**P2**（已量測：至今實際危害 0）

---

## 一、結論（先講最短的版本）

真錢下單路徑上，每一個對外呼叫失敗時都做兩件事：**擋單（fail-closed）＋ 記進健康帳（`_note_fail`）**。
只有一個例外——**設槓桿**。它失敗時只印一行警告，然後**照樣把單送出去**，而且**完全不進健康帳**。

這代表兩件事：

1. 「風險由止損距離決定，槓桿只影響資金效率」這句寫在 `ensure_leverage` docstring 裡的理由，**只有在槓桿真的被設成功時才成立**。設失敗時交易所沿用的是舊值，v84 那條「清算永不先於止損」的不變式就悄悄不再成立，而程式**沒有任何回讀去發現這件事**。
2. 如果哪一輪「只有設槓桿失敗、其他都正常」，那一輪會被健康帳判成**完全健康**——單照送、帳面全綠。這跟 v151 治掉的「安靜＝痊癒」是同一物種，只是換了一個入口。

## 三、那個洞什麼時候會真的打開

401 這種**認證類**故障永遠會讓所有呼叫一起死，所以它反而安全。危險的是**只打到設槓桿、打不到下單**的錯誤類別。最現實的一種：

> **交易所在同一 `instId`／`posSide` 已有持倉時，會拒絕調整槓桿。**

這是槓桿端點專屬的錯誤，**在定義上不可能與查單失敗同輪共現**——也就是說它正好落在唯一沒有防護的那格。

而「同幣同向已有持倉」這個狀態在真錢路徑上是**可達的**：r39（`docs/org/2026-07-31-真錢路徑缺同幣同向在場閘-v130補丁未過河.md`）已經確認 v130 的「同幣同向已在場」閘從沒移植到真錢路徑。兩個發現在此接起來——r39 是入口沒關，本篇是入口沒關之後會撞到的第二道傷。

## 四、危害方向校正（怕錯方向了）

直覺會說「槓桿沒設好＝爆倉風險」。**這個方向是錯的**，逐倉（isolated）下反而相反：

- 張數由風險預算決定，與槓桿無關：`sz = 風險USD ÷ |entry−stop| ÷ ctVal`（:365–397），所以**名義值是固定的**。
- 逐倉保證金 ＝ 名義值 ÷ 實際槓桿。**實際槓桿越高，押的保證金越少。**

以真錢參數（`RISK_USD=20`、`LEVERAGE=20`）舉一個具體例子：

| | 應設槓桿 | 卡在舊值 |
|---|---|---|
| 止損距離 | 10% | 10% |
| `leverage_for_trade` 算出 | `max(3, min(20, 70/10))` = **7x** | （設失敗，交易所仍是 **20x**） |
| 名義值 | 20 ÷ 0.10 = 200 U | 200 U |
| 逐倉保證金 | 28.6 U | **10 U** |
| v84 自身尺度下的清算距離（70/lev） | 10% ＝ 止損，剛好守住 | **3.5% ＜ 10%** |

所以真正的危害不是「賠更多」，而是：

1. **交易在走到自己的止損之前就先被清算掉**——一筆本來還在計畫內、可能翻回來的單被提早殺死。這是 EV 上的傷，不是本金上的傷。
2. **出場原因被記錯**：倉位是被清算消失的，交易所側的止損單從沒被觸發。帳本會把它記成別的東西，`net_r` 也就歸因錯——與 r38 那筆「熔斷記帳記錯日」同一物種。
3. 金額上界反而更小（本例約 10 U ≈ 0.5R，小於計畫中的 1R）。**這是巧合帶來的緩衝，不是設計**。

反方向（交易所卡在 v99 那個預設 3x、程式以為 20x）則多半會**自己撞成保證金不足而被拒單**——名義值上限 600 U 在 3x 下要 200 U 保證金。那是「不小心 fail-closed」，安全但不是靠設計。

## 五、可達性收斂（別把它講得比實際大）

`leverage_for_trade = max(3, min(LEVERAGE, 70/止損%))`，真錢 `LEVERAGE=20`：

- **止損 ≤ 3.5% ⇒ 算出來就是 20x**。而 20x 已是上限，交易所的舊值**不可能比它更高**，所以這種單即使設槓桿失敗也**沒有危害**。
- **止損 > 3.5% ⇒ 算出來 < 20x**，這才是「舊值可能比應設值高」的危險帶。

美股代幣的 1h 突破單止損通常偏緊（多落在 20x 那格），所以這主要是**加密側**的風險帶。

順帶一個值得記下的結構問題：**模擬盤演不出這一齣**。模板 `LEVERAGE = 5`，危險帶要止損 > 14% 才進得去；真錢複本 `LEVERAGE = 20`，止損 > 3.5% 就進得去。**真錢那一份的暴露面比模擬盤大得多，而模擬盤跑再多輪也不會撞到。**

## 六、修法（交辦 CEO Session・P2・與 r39 的修 A／修 B 同檔，建議併一次做完）

改 **模板** `tools/atk_consumer/consume_intents.py`，再用 `make_live_copy.ps1 -GenerateOnly` 產生真錢複本（勿直接改 `_live.py`，會被下次產生蓋掉）。

- **修 C-1（一定要做）**：`ensure_leverage` 失敗時呼叫 `_note_fail("leverage_fail", ...)`。理由：讓「安靜」不再等於「健康」。這一項單獨就值得做，不改任何交易語義。
- **修 C-2（精準版擋單，成本極低）**：只有在 **算出來的 lev < LEVERAGE** 時，設槓桿失敗才 fail-closed（`place()` 回 `False`，本輪不下、下輪重試）；算出來 **== LEVERAGE** 時維持現行「只警告、照下」。
  理由見第五節：lev == 上限時舊值不可能更高，擋單純屬白擋。這條規則讓防護只花在真的有風險的那一格，代價是最多延一輪。
- **修 C-3（可選）**：`lev < LEVERAGE` 時回讀交易所實際槓桿，實際值 ≤ 應設值才放行。比 C-2 準，但多一次 API 呼叫、也多一個會失敗的東西；**建議先做 C-1＋C-2，觀察若干輪再決定要不要 C-3**。

⛔ 不要順手把 `LEVERAGE`、`RISK_USD`、`NOTIONAL_CAP_USD` 一起調——那是另一個題目，要有自己的量測，勿夾帶。

### 驗收測試（三條，純函式／可離線跑）

1. `ensure_leverage` 失敗 **且** 算出 lev < LEVERAGE ⇒ `place()` 回 `False`、**零腿送出**、health 出現 `leverage_fail`。
2. `ensure_leverage` 失敗 **但** 算出 lev == LEVERAGE ⇒ 維持現行行為（照下、只警告），health 仍記 `leverage_fail`。
3. `leverage_for_trade` 邊界：止損 3.5% → 20；10% → 7；30% → 3（下限）；entry/stop 缺值 → `min(max_lev, 5)`。

執行器非常駐，**不需要 RB-1 停機流程**；但須 `py_compile` ＋ `tests/test_atk_consumer.py` ＋ `make_live_copy.ps1 -GenerateOnly`。
