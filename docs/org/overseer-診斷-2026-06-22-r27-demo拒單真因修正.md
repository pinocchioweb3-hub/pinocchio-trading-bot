## 二、三點關鍵修正（推翻舊 escalation 假說）

### 1. ⛔「請去改 OKX 模擬盤保證金模式（51010）」一說 **未被任何一筆活線記錄證實**
連續多輪對使用者的行動清單以「多為 51010，須改單幣種/跨幣種保證金模式」為最高優先。但 36 筆 rejected 中 **51010 出現 0 次、51121 出現 0 次**。這是一個**從未被 demo_trades 證實的假說**，卻被當成使用者唯一硬 blocker 反覆推送。依紅線③（不捏造）與「驗活的事實」紀律，**此假說應降級為「未證實」，不再當成既定事實向使用者推送**。

### 2. 真正可知的最大拒因（BadSymbol, 17 筆）是 **daemon 側、非使用者側**，且**已於 ~24h 前停止**
BadSymbol 標的清單含 **US 股票代號**（SPCX / SNDK / MU / BEAT）被送進 OKX **永續**宇宙下單 = 跨資產路由洩漏（美股訊號不該進 demo 永續操盤手）。此非使用者能修，屬 task#54（demo_op 未上市符號治本）射程；最近一筆 24.3h 前，疑似某次變更後已自然停止，但**根因（美股代號為何流入 demo_op）未經確認治本**，僅「目前安靜」。

### 3. 最高槓桿的可修項是**觀測缺口**：19 筆泛用 `code:"1"` 失敗**未持久化 OKX 原始 sCode/sMsg**
- 這 19 筆含 **BTC、ETH**——兩者確定掛在 OKX demo 永續，故其失敗**不是** BadSymbol，是真正的下單失敗（餘額／模式／規格之一），但**真因被泛用包裹吞掉**。
- 沒有原始 sMsg，**監督員與使用者都無法確認**這 19 筆到底是不是 51010。這正是為什麼「改保證金模式」假說既無法證實、也無法排除——**資料根本沒記**。
- 治本＝在 demo_op 下單失敗路徑持久化 OKX 原始 `sCode`+`sMsg`（接 demo_trades.note 或新欄）。這是**解開整個 demo 成交瓶頸的鑰匙**，但屬 daemon 常駐模組 = **RB-1，須 CEO Session 人工監督**，監督員無人值守不動。
