## 改了什麼（母本 `tools/atk_consumer/consume_intents.py`）

### 修 A：下單前的同幣同向在場閘

新增純函式 `dup_open_same_side(open_map, inst_id, pos_side)`，接在主迴圈日虧熔斷檢查
之後、張數換算之前：

```python
if dup_open_same_side(_load_positions().get("open", {}),
                      intent["inst_id"], intent["pos_side"]):
    print(f"⏸ {iid} {intent.get('symbol')} 同幣同向已在場——本輪不接"
          "（OKX hedge 併倉會使已實現損益無法歸屬兩單）")
    continue
```

三個設計選擇，都是刻意的：

1. **`continue` 而不記 `done`**——沿用熔斷日的既有慣例。不是永久拒絕這張 intent，
   只是這一輪不接；倉平掉後若 intent 還沒過期就自然接上。
2. **每次迴圈重讀 `_load_positions()`**（而非迴圈外讀一次）——同一輪裡若前一張同幣同向
   剛下成功並寫進 `open`，後一張必須看得到它。讀一次會漏掉同輪重複。
3. **反向不擋**——hedge 模式同幣多空並存是合法的，擋過頭會誤殺正常對沖。

依據：v130 在模擬盤已實證同一筆 realizedPnl 被雙重記帳、R 虛增 +1.30
（`l3_dispatcher/demo_operator.py:419-428`），真錢側從來沒有這道閘。

### 修 B：熔斷記帳吃「成交當下」的 UTC 日

`_realized_pnl_since()` 迴圈本來就在讀 `f["ts"]`，改為連同**最後一筆 fill 的 ts** 一起回傳
（回傳型別 `float | None` → `tuple[float, float | None] | None`）。對帳端：

```python
dk = _day_key(last_ts) if last_ts else _day_key()      # 取不到 ts 退回舊行為，寧可近似不漏記
dk = max(dk, _day_key(time.time() - 14 * 86400))       # 夾進 14 天保留窗，別被下方修剪吃掉
```

第二行是 r39 特別點名、修 B 自己會引進的新洞：下方 `day_pnl` 只保留 14 天，
回填比保留窗更舊的日期會在**同一次呼叫裡**被立刻剪掉、損益無聲蒸發。

副帶：了結訊息從「今日累計」改成「記入 YYYY-MM-DD UTC，該日累計」——
既然記帳日可能不是今天，訊息就不該再說「今日」。
