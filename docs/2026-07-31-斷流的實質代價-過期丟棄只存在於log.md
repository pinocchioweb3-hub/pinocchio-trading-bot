## 二、本輪的新發現：斷流的代價是隱形的

### 事實（量測，非推論）

| 項目 | 數值 |
|---|---|
| 連續 fail-closed 輪數 | 1071 → 1079（仍在長） |
| `last_ok_ts` | 停在 17.9 小時前，**未前進** |
| 故障類別 | `auth_ip_whitelist`（單一類別，未變） |
| 待處理 intent | **0 筆**（33 筆全在 done） |
| **因過期被永久丟棄** | **4 筆**：SOXL、SNDK、SNDK、MU |

⛔ 判恢復的規矩不變（r33 假痊癒教訓）：看「有沒有成功呼叫」，不看「有沒有故障訊息」。
本輪 `last_ok_ts` 沒動＝**未恢復**。

### 破口

`consume_intents.py` 的過期分支長這樣（改動前）：

```python
if now_ms > intent.get("expires_at", 0):
    print(f"⏭ {iid} {intent.get('symbol')} 已過期——跳過")
    done.add(iid)
    continue
```

一行 print，然後這筆訊號就永遠消失了（過了 `expires_at` 不會補送）。於是：

* 健康檔沒有任何欄位知道「這場斷流吃掉幾筆」；
* 監督帳本、Telegram 一個字都沒提；
* 唯一的證據是 837KB `atk_live.log` 裡 grep 得到的 4 行文字。

**這是同一物種的第五次**：v164（讀失敗→當成沒有故障史）、v166（寫失敗→只寫進 log）、
v167（用旗標代理「活著」）、以及 r66 自己踩的（把 `pushed:false` 當成沒人推過）。
共同形狀是——**要用來下判斷的量，只以 log 文字或代理值存在，等於不存在。**

### 為什麼這件事現在才重要

帳本給使用者看的那行字寫著「每輪皆 fail-closed 未下單（**零損失**）」。
這句話對「沒有下錯單」成立，但讀起來像「不急」。實際上拖越久丟越多，
而丟掉的訊號**修好也追不回來**。使用者要決定「多急著去補白名單」，
靠的正是這個數字。

## 三、v169 的修法

### ① 執行器端（`tools/atk_consumer/consume_intents.py`）

* 新增 `_ROUND_EXPIRED` 本輪丟棄帳（比照 `_ROUND_FAILS` / `_ROUND_OKS`），每輪清空。
* 過期分支除了 print，另外把 `{intent_id, symbol, side}` 記進去。
* `update_health()` 新增 `expired` 參數，分兩本帳：
  * `expired_dropped_total`＝含正常老化（訊號本來就有時效）；
  * `expired_dropped_during_fault`＝**斷流期丟的**，才是「這場故障的代價」。
    混在一起會被日常噪音灌水，數字就沒有意義。
  * `expired_dropped_recent`＝最近 20 筆明細（含當時的故障類別），有上限。

**⛔ 最容易做錯、也是本次特別立測試守住的一點**：
斷流期的丟棄**恰好發生在空轉輪**——intent 全過期 ⇒ 一次呼叫都沒發出 ⇒
`fails` 空、`oks == 0`，正是 `update_health` 會**提早 return** 的那條路徑（v151 加的）。
記帳若寫在提早 return 之後，唯一要記的情境就一筆都記不到＝白修。
測試 `test_expiry_during_an_outage_is_attributed_to_the_fault_on_an_idle_round` 就是釘這件事。

### ② 帳本端（`l3_dispatcher/ceo_oversight.py`）

* `live_exec_verdict()` 讀 `expired_dropped_during_fault`，有值才在阻塞描述後面接一句：
  「斷流期間已有 N 筆訊號逾時被**永久**丟棄（過期不補送，修好也追不回來）」。
* 「零損失」措辭改為「**無金錢虧損**」——沒有下錯單是真的，但不等於沒有代價。
* ⛔ 代價只影響**措辭**，不影響「是不是阻塞」的判定：streak 未達門檻、或健康檔太舊
  （執行器沒在跑），照樣回 None。壞值（字串／None／list／NaN）只讓代價從缺，
  不可害死整個阻塞判定——否則一場真斷流會從帳本上憑空不見。

### 沒有做的事

* **不新增 Telegram 告警**。r66 剛把噪音壓下去，不在同一天加回去。代價走帳本，不走推播。
* **不回填**那 4 筆到線上健康檔。它們發生在計數器存在之前；把數字手寫進真錢側的
  健康檔＝製造資料，紅線③。log 裡的 4 筆是本文的量測結果，計數器從現在起才開始記。
