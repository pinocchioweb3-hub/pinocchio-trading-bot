# 乾淨環境收集數落差：結案（監督員 r138，2026-08-03）

## 一句話

**乾淨 clone 少收集的 8 筆測試，全部出自同一個檔，成因是刻意的跳過、不是壞掉；
但那個跳過是「靜音」的——CI 全綠與「這 8 條跑過了」長得一模一樣，而它們守的正好是紅線③的形狀。**

## 量到的事實（可複驗）

同一個 commit `27bafad`（v247），兩邊都用 `pytest --collect-only -q`：

| 環境 | 收集數 |
|---|---|
| 本機工作區 `C:\Users\user\OneDrive\桌面\交易機器人` | **2104** |
| 乾淨 worktree（`git worktree add --detach <tmp> HEAD`） | **2096** |
| 差 | **8** |

逐筆比對 node id（`comm -23`），8 筆全部落在同一個檔：

```
tests/test_trust_source_unreadable.py::test_project_facts_empty_object_is_not_missing
tests/test_trust_source_unreadable.py::test_project_facts_missing_stays_not_found
tests/test_trust_source_unreadable.py::test_project_facts_ok
tests/test_trust_source_unreadable.py::test_project_facts_unreadable_is_not_reported_as_missing
tests/test_trust_source_unreadable.py::test_status_missing_vs_unreadable_vs_ok
tests/test_trust_source_unreadable.py::test_verification_missing_is_error_too
tests/test_trust_source_unreadable.py::test_verification_ok_still_works_and_never_leaks_current
tests/test_trust_source_unreadable.py::test_verification_unreadable_is_error_not_silent_empty
```

反向也查了：乾淨環境**沒有**任何本機收不到的測試（`comm -13` 為空）。
也查了「未納版控的測試檔」這個假說——**不成立**：`tests/` 底下沒有任何未追蹤的 `test_*.py`。

## 成因

`tests/test_trust_source_unreadable.py:38-40` 有一個 module-level skip：
若 `platform/api/data_access.py` 不存在就整個模組跳過。而 `platform/` **整棵子樹未納版控**
（git status 長期顯示 `?? platform/`，是待使用者決策事項之一），新 clone 當然沒有它。

所以：**不是 bug、不是壞掉、也不需要修那個 skip**（它是為了避免整份 collection error 而寫的，寫法正確）。

## 為什麼仍然要處理

跳過本身沒錯，錯在它**不出聲**：

* `pytest -q` 在兩邊都是綠燈、退出碼都是 0；
* 唯一的差別是收集數 2104 vs 2096，而沒有人會把兩個環境的收集數並排看；
* 於是「CI 全綠」被讀成「這 8 條防線跑過了」。

那 8 條守的是什麼：信任頁的資料源（verification-status.json）壞掉時，
舊碼會回成「gates=[] + 誠實聲明全 None + **沒有 error 旗標** + 筆數照送」，
前端只在 `v.error` 時才提早返回 ⇒ 對外只剩**數字**、掉了「這是紙上交易／尚未證實」那段限定語。
**這正是紅線③的形狀。** 在任何乾淨 clone／CI 上，這條防線從來沒有被執行過。

## 這輪做了什麼

新增 `tests/test_collection_gap_visibility.py`（4 條，均通過）：

* 掃 `tests/` 找 module-level skip（`allow_module_level=True`）與 `pytest.importorskip`；
* 每一個都必須寫進 `DECLARED_CONDITIONAL_SKIPS`，且必須同時寫下**成因**與**缺條件環境下的代價**；
* 未申報 ⇒ 紅；申報了但跳過已消失 ⇒ 也紅（清單不得腐爛）；
* 另有一條「掃描器非虛設」檢定（掃不到東西＝掃描器壞了，不是真的沒有）。
* 反向驗證：把申報清單清空後，該檢定如預期變紅並列出 4 個檔（＝非虛設檢定）。

目前已申報 4 檔：`test_trust_source_unreadable.py`（platform/ 未納版控）＋ 三個 matplotlib `importorskip`。

⛔ 這輪**沒有**去動那 8 條的跳過本身——要讓它們真的在 CI 跑起來，前提是
`platform/` 納入版控，而那是待使用者決策的事項（PUBLIC repo，需先確認該子樹無敏感內容）。

## 留給使用者的一句話

待決策項「platform/ 與 docs/trust-site/ 是否納入版控」現在有了可量化的代價：
**不納入 ⇒ 8 條防止對外只剩數字（紅線③形狀）的測試，在任何乾淨環境都不會執行。**
