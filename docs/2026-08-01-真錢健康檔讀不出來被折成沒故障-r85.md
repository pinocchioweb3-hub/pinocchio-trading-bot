## 一、v189 線上實證（本輪最硬的一筆事實）

r80／r84 連續兩輪記著「memguard 常態清掃至今線上零次觸發 ⇒ 零實證」。本輪 grep
`watchdog.log` 首次找到兩行：

```
L886: 2026-08-01 07:34:04 [memguard] 常態清掃：清 4 個殭屍 runner（commit 56%,未達緊急線,純衛生）
L887: 2026-08-01 10:34:05 [memguard] 常態清掃：清 4 個殭屍 runner（PID [12824, 3804, 21788, 7252]）（commit 57%,未達緊急線,純衛生）
```

- L886（07:34）是 **v189 之前**的舊碼（v189 於 08:11 提交）——只有數字、沒有 PID，
  事後**無從查證它到底殺了誰**，這正是 v189 的動機。
- L887（10:34）是 v189 之後的新格式。對照 `watchdog.py:307`，那個數字取自
  `_kill_all()` 的 `killed`，而 `killed` 只收 `taskkill` **rc=0** 的 PID。
- **獨立交叉驗證**：本輪逐一 `Get-Process -Id` 查那 4 個 PID，**四個全部 GONE**。
  ⇒ v189「清了 N 個」改成驗證過的數字這件事，**已在線上發生、且數字經第二法覆核為真**。

順帶量到的兩件事（都不是故障）：

- 兩次清掃間隔 3 小時，但 `MEM_COOLDOWN_SEC` 只有 600 秒 ⇒ **不是冷卻在擋**，是
  「≥4 個且年齡 ≥90 分鐘」的條件到 10:34 才再次成立。行為與設計一致。
- v190 的 `[detect] daemon 行程探測失敗／無法判讀` 至今 **0 次**。那是預防性封堵，
  0 次＝探測一路正常，**不等於已驗證**——⛔ 不得宣稱 v190 已在線上實證。

## 二、盤點：`l3_dispatcher` 的「讀取失敗折成確認沒有」候選 22 處

方法：AST 掃全目錄，找「`except` 區塊直接 `return` 空容器／0／False／None，且 `try`
區塊碰到的名字帶部位／帳本／損益語意」的寫法，得 22 處候選，逐一人工判讀。

> ⛔ 盤點工具自己先踩了一次同物種的坑：第一版用 `encoding="utf-8"` 讀檔，`dispatcher.py`
> 有 UTF-8 BOM ⇒ `ast.parse` 拋 SyntaxError ⇒ 那一檔被略過。改成 `utf-8-sig` 重跑，
> 候選數仍是 22（該檔本來就沒有這種寫法）——重點是這件事現在是**量出來的**，不是
> 假設出來的。

判讀結果分三類：

## 三、v191：修的是哪一處、為什麼它比 B 類嚴重

```python
def _read_live_exec_health() -> dict:
    try:  ... json.load ...
    except Exception:
        return {}          # ← 檔不存在、與檔壞掉，折成同一個答案
```

而三個判定的第一行都是 `if not health: return None`：

- `live_exec_verdict` → None（沒有現行故障）
- `live_stall_verdict` → None（沒有停擺）
- `pnl_gap_verdict` → None（沒有漏記）

⇒ 健康檔一旦壞掉（半截檔、權限、編碼、或被寫成 list），帳本上真錢那一欄會是**整片
空白**，與「一切正常」長得一模一樣。任何人（包括下一輪的監督員）看到「沒有真錢阻塞」
都會讀成痊癒——**r33 假痊癒的形狀，換第 11 個入口**。

修法（兩處，都在 `ceo_oversight.py`）：

1. `_read_live_exec_health()` 拆開兩種狀態：
   - `FileNotFoundError` → `{}`（**未知**，可能根本還沒部署過執行器，保持沉默）
   - 其他例外 → `{"_read_error": <例外類別名>}`（檔在、讀不出來＝**故障**）
   - 合法 JSON 但不是 dict → `{"_read_error": "NotADict"}`（舊碼會原封不動往下傳，
     下游 `.get` 當場爆，再被 `build_snapshot` 的 `except` 吞掉，同樣是一片空白）
2. `live_stall_verdict()` 新增專屬分支，文字直說「健康檔存在但讀不出來（<類別>）」，
   `user_actionable=False` ⇒ 進 `system_faults` ⇒ 可蓋成 STALLED（該 push CEO，
   不是丟給使用者）。
   ⛔ 不可讓它掉進既有的「沒有可信的更新時間戳」那句：那句在講「檔讀得出來但欄位缺」，
   把「我們根本沒讀到內容」說成「讀到了、但時間怪怪的」——方向雖同、事實不同。
