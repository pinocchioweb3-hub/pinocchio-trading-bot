## 2. 歸因校正：把「浮動 IP 結構問題」縮小回「一個 IP 沒補」

r24 當時的結論是「根因是浮動 IP 會復發、不是設定錯」，據以在待辦裡列了
放寬到 ISP 網段／搬固定 IP 主機等選項。本輪覆核後**縮小該結論的適用範圍**：

- `grep -o "Your IP [0-9.]*" atk_live.log | sort | uniq -c` → **799 次，只有一個 IP**。
- 日誌無輪替（同目錄只有一個 `atk_live.log` 加一個舊的壞碼 `.bak`），
  時間跨度 **> 29 小時**。

所以 r24 的觀察（7/29 記錄的白名單 IP ≠ 7/30 錯誤訊息裡的 IP）**仍然成立**——
IP 確實在那之間換過一次。但「會週期性復發」這個推論**被 29 小時 / 799 次的穩定期削弱了**：
換完之後它一次都沒再動。

**這件事為什麼重要**：上一版待辦把使用者的下一步框成「要先處理一個結構問題」，
而實際上**補一個 IP 就會通**。降低要求＝提高這個唯一真阻塞被清掉的機率。
網段放寬／固定 IP 仍是可談的加強，但不是前提。

> 方法論記一筆：r24 與本輪的差別不是拿到新資料，是**把同一份日誌拿去數分佈**
> （uniq -c）而不是只讀最新那一行。「根因會復發」是個關於**分佈**的宣稱，
> 不能只用兩個時間點推出來。
