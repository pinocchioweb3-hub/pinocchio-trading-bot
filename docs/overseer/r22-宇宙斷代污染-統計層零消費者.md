## 二、缺口（本輪主要發現）

### 2.1 零消費者

```
grep -rn "universe_source" --include=*.py .
→ 僅 4 檔命中：l3_dispatcher/plan_snapshot.py（寫）
              l3_dispatcher/universe_provenance.py（存）
              l3_dispatcher/watchlist.py（產）
              tests/test_universe_provenance.py（測）
```

**沒有一個統計／優化／晉升模組讀它。** 也就是 v142 目前只是「留痕」，還不是「隔離」。

### 2.2 污染就發生在這一行

`l3_dispatcher/auto_optimizer.py:53 _load_closed_paper()`：

```python
def _load_closed_paper(days: int = 120, db=None) -> list[dict]:
    cutoff = int(time.time() * 1000) - days * 86400 * 1000
    ...
    where = ("WHERE status='closed' AND setup='deepdive' "
             "AND IFNULL(exit_reason,'')!='entry_expired' AND entry_at>=?")
```

**120 天視窗同時涵蓋兩代**（CG 死於 7/08、免費源上線 7/29，相距僅 21 天）。

### 2.3 這是 v114 已修過的同一種蟲

同一個函式的註解就是前例：

> v114（稽核 rank3 治本）：只收加密 deepdive——池化桶過去混入美股 us_breakout 樣本
> ＝拿另一個引擎的成交行為替加密參數背書（統計污染）。

**v114 擋的是「跨引擎」污染，靠的是 `AND setup='deepdive'`。
本輪發現的是「跨宇宙世代」污染，同一位置、同一species、目前沒有對應的 AND 條件。**
而 v142 的 commit message 早已預告過這件事：
「topN_agreement=0.0＝選股實質已換，兩代樣本不可合併統計」——留痕做了，**消費端沒做**。

### 2.4 量化：現在稀釋，但方向是惡化

優化器 120 天視窗內 closed／deepdive／非 entry_expired 樣本 **157 筆**：

| 世代 | 筆數 | 說明 |
|------|------|------|
| CG 時代（≤ 07/08） | **147** | 凍結不再增加，且會逐日滑出 120 天窗 |
| 空窗（07/08–07/29） | 2 | 宇宙全盲期 |
| 免費源時代（≥ 07/29） | **8** | **以約 10 筆/日增加中** |
| 其中帶 `universe_source` 欄 | 5 | 其餘只能靠 `entry_at` 反推世代 |

→ 目前污染比僅 5%（8/157），**但分子每天 +10、分母每天在老化滑出**。
數週內免費源樣本將成為多數，而**交叉期間每個桶都是兩種選股邏輯的混血**。
`auto_optimizer` 過 L2 後是**直接寫活參數**的（依 2026-06-20「復盤引擎不設參數鎖」決策，
把關全靠統計嚴謹度）→ 混血樣本餵出的晉升，就是錯誤參數直接生效。

**時間敏感性**：現在各桶 n 多半仍低於 L2 門檻＝**還沒有錯誤晉升發生**，
這正是修的窗口；等到 n 跨過門檻才修，前面的晉升要全部回頭清算。
