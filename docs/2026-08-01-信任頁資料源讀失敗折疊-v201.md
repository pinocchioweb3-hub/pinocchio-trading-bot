## 一、這一次的下場：不在流程，在**對外呈現**

`verification()` 的舊碼只有一行：

```python
data = _read_json(_TRUST_DATA / "verification-status.json") or {}
```

關鍵在於這個回傳值裡的東西**來自兩個不同來源**：

| 欄位 | 來源 |
|---|---|
| `gates`（驗證閘門）、`note_on_metrics`、`honest_backtest_conclusion_zh`、`verify_how` | verification-status.json ← **只有這一個檔** |
| `paper_progress`（紙上交易筆數）、`live_progress`（實倉筆數） | paper_journal 模組、trade_journal.db ← **另外兩個來源** |

所以那個檔一壞（半截 JSON／權限／編碼），`or {}` 會讓左半欄整排變成 `None`，
右半欄**完全不受影響照送**，而且回傳裡**沒有 error 旗標**。

實測舊碼（本輪行為探針，非推論）：

```json
{ "phase": null,
  "note_on_metrics": null,
  "honest_backtest_conclusion_zh": null,
  "gates": [],
  "paper_progress": { "n_closed": 369, "n_open": 3, "target": 100, "enough": true },
  "live_progress":  { "n_closed": 0, "target": 30, "note_zh": "尚未開始實倉" } }
```

前端 `platform/web/views/trust.js:177` 只在 `v.error` 為真時才提早返回；
上面這包沒有 `error`，於是它會照常往下畫出**兩條筆數進度條**——
而「這是紙上交易樣本、非真實績效」「扣費後未證實有 edge」那兩句限定語**消失**。

對外只剩數字、沒有限定語。這正是紅線③的形狀，而觸發它的不是誰寫錯文案，
是一個讀檔函式把「讀不到」寫成了「沒有」。

`project_facts()` 的舊碼則是直接回 `NOT_FOUND`「project-facts.json 不存在」——
對讀失敗說謊。壞檔要修、缺檔要補，兩種處置不同，訊息就不能一樣。
另外 `if not data` 還會把合法的空物件 `{}` 一併誤報成不存在。

## 二、修法

新增三態讀取：

```python
def _read_json_status(path) -> tuple[dict | None, str]:
    # status ∈ {"ok", "missing", "unreadable"}
    # FileNotFoundError → missing；其他例外／JSON 壞／非 dict → unreadable（並留 log）
```

- `project_facts()`：`unreadable` → `SOURCE_UNREADABLE` 並明說「這不等於『不存在』」；
  `missing` → 維持 `NOT_FOUND`；`{}` 不再被誤判。
- `verification()`：`status != "ok"` → **整塊 fail-closed**，`error: True`，
  且 `paper_progress` / `live_progress` / `gates` **一顆數字都不輸出**。
  寧可整塊不出，不可只出一半。前端既有的 `v.error` 分支會顯示
  「驗證進度資料暫時讀不到。」——不需要改前端。

`missing` 也走 fail-closed，理由與 `unreadable` 相同（缺檔一樣會變成只剩數字）。
